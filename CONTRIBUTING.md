# Contributing

Thanks for wanting to help with Voice!

## Quick overview

| You want to…                 | Do this                                                                                          |
|------------------------------|--------------------------------------------------------------------------------------------------|
| Report a bug                 | [Open a bug report](https://github.com/PaulWoitaschek/Voice/issues/new?template=bug.yml)         |
| Suggest a feature or change  | [Open a feature request](https://github.com/PaulWoitaschek/Voice/discussions/new?category=ideas) |
| Fix a bug or build a feature | Open an issue, not a pull request. See [Pull requests](#pull-requests).                          |

## Bug reports and feature requests

These are the most useful contributions. A good bug report with clear steps to reproduce helps more than a pull request.
Search the existing [issues](https://github.com/PaulWoitaschek/Voice/issues) and [discussions](https://github.com/PaulWoitaschek/Voice/discussions) first and upvote what's already there.

For a feature request, describe the problem you want solved, not only the solution you have in mind.

## Pull requests

Voice only accepts pull requests I asked for.

I build Voice myself, with AI tools. Writing code has become cheap. Reviewing and maintaining it has not.
A pull request rarely saves me time: reviewing someone else's change and fitting it into the architecture usually takes longer than building it myself.
And every feature that gets merged has to be maintained for years.

This is nothing personal, and your help is still welcome. It's just that [bug reports and feature requests](#bug-reports-and-feature-requests) help me more than code.

Sometimes I'll ask someone to help with the code, for example when a fix needs a device or expertise I don't have.
If that's you, read [Development](https://voice.woitaschek.de/development/) and [Architecture](https://voice.woitaschek.de/architecture/) first.
